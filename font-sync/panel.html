1准备一个 GitHub 令牌（令牌 = 插件访问你仓库的钥匙）

第一次使用需要你在 GitHub 上生成一个 classic token，勾选 repo 这一项就够了。 插件用它在你自己的账号下建私有库、传字体包。

打开 GitHub 建令牌页（已预勾 repo） 管理已有令牌
建令牌时只要勾 repo 一项（整块，含子项）。不要勾 workflow、admin:org、 delete_repo —— 这个插件用不到。
页面最上面 Expiration 建议选 No expiration 或 1 年：令牌过期后同步会突然 401，届时回来换一个就行。
令牌形如 ghp_xxxxxxxx…，只显示一次，生成后请立刻复制。它等同于密码，别发群里、别提交进仓库。

2把令牌粘进来

粘贴后点「测试并保存」。插件会用它读一次账号名，确认有效，然后加密存到本机。

想用多个账号？直接把另一个账号的令牌粘进来再点「测试并保存」—— 新账号会加进下面的列表， 每个账号一行，非当前的那行有「切换」按钮。用哪个账号同步，取决于当前选中哪一个（上方状态点）。

3这台机器上存了什么

令牌绝对不在插件目录里。它优先存进 Windows 凭据管理器（控制面板 → 凭据管理器 → Windows 凭据 → FontManager/font-sync/vault），由 Windows 用你当前账户的密钥加密保管； 凭据管理器不可用时回退到 %APPDATA%\FontManager\font-sync\vault.bin （DPAPI 加盐密文）。两者都不可用就只留在内存里，绝不写明文。 插件 ZIP、插件目录、代码里都没有令牌，拷走插件也带不走。旧版写在插件目录的 secret.bin 会在首次读取时自动迁移并删除。

插件目录里只有明文 config.json（账号名、仓库名、同步规则、公开的 Client ID，不含令牌） 和 state.json（每族上次同步的哈希）。

上传和复制令牌需要先验证身份：点这两个按钮时，会要求你在浏览器登录「令牌所属」的 GitHub 账号并输入一次性验证码（Device Flow，插件碰不到你的密码，也不需要 client_secret）。 验证只在本进程内存里保留 5 分钟；把字体下载回本机不需要验证。

插件要做的事调用的接口需要权限为什么要它

不需要、也不会碰的权限

    令牌只保存在本机插件目录，请求只发往 api.github.com 和你填的那个仓库。

    为什么不用 fine-grained 令牌

    fine-grained 令牌必须先指定能访问哪些仓库。而本插件要「首次同步时自动帮你建私有仓」， 新建的库不在令牌的授权名单里，建仓和上传都会被拒。classic 令牌的 repo 覆盖你名下所有仓库，才能做到「填个名字就能用」。

    如果你已经有一个现成的私有库、只打算往里传，用 fine-grained 也行，但要给它 Contents: Read and write + Administration: Read and write（能建 release 才不会卡住）。

    插件对 FontManager 本体的权限

    权限用途说明
    read:fonts读字体清单（GET /fonts） 要知道本地有哪些字族、每个族在哪个目录，才能按族打包；「补缺」也用它判断本机已有哪些族。只读，不改字体、不删文件。
    write:fonts触发重扫（POST /fonts/scan） 下载回来的字体要让界面立刻看见，不用你手动点一次「重新扫描」。
    read:snapshot读快照清单（GET /snapshots） 「补缺」页要知道快照里记了哪些字族，才能对比出这台机器缺什么。0.8.0 新增 —— 老令牌没有它，重启 FontManager 后自动拿到。只读，不动快照内容。
    /health启动自检确认本地 API 与令牌可用，失败时在日志里说清楚。

    除此之外不发任何请求给主程序。详细约定见主程序仓库的 docs/PLUGINS.md。

    点下面的按钮，用你现在的令牌真去问一次 GitHub，逐项给出结果。

    从零开始：五步配好

    1. 确认插件已启用。FontManager → 设置 → 插件，本插件那一行开关打开；没看到就点「重新扫描」。 装在 插件目录\font-sync 这个文件夹里。
    2. 建令牌。点这里 打开 GitHub 建令牌页（repo 已预勾）→ 页面底部 Generate token → 复制 ghp_…。 非中文界面路径：Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token (classic)。
    3. 存令牌。回到「账号与令牌」页 → 粘贴 → 测试并保存 → 看到「已连接 你的名字」。 若提示缺 repo，回 GitHub 给这个令牌补勾。
    4. 选库 —— 两种做法挑一个，都是一步到位。
      • 已经有私有库：点「刷新列表」→ 在下拉里挑一个 → 点「用这个库」。 插件会当场检查它是不是私有、能不能被匿名读到，通过就自动保存成当前库。
      • 还没有库：点「建好并用它」。名字默认 fontmanager-fonts，想改就改。 插件建的是 private 仓库，建完自动设为当前库，不用再去网页上点一遍。
      成功的标志：页面中间出现绿色一条「当前库：你的名字/xxx（已就绪）」。 要用手上组织的库、或下拉里没列出来的，展开下面的「手动填写所有者 / 仓库名」。
    5. 先预演，再正式传。
      • 点「预演一次（不传）」：只统计多少族、共多少 MB，不打包、不上传，几秒钟出结果。 这些数字就是这次要动的东西，看着合理再往下走。
      • 确认没问题 → 「立即同步（全部）」。首次是全量，时间主要看你的上行带宽 （整库几个 GB，以小时计；之后只传变化）。
      • 以后改了一两款字体：右键那个字族 →「同步这个字族到 GitHub」，只处理它一个。

    1. 装同一个 FontManager，把 font-sync 插件目录放进去（或用同一份 ZIP）；
    2. 令牌可以用同一个，也可以另建一个（插件支持存多个账号并在设置里切换）；
    3. 仓库填同一个 所有者/仓库名；
    4. 首次同步：只传这台机器上「和远端不同」的族，远端已有的不重复传。

    两台机器同时传也不会互相覆盖：每个族的包名带内容哈希，记账提交用「快进否则重试」，冲突会自动重来。

    常见问题

    点了同步没反应 / 提示「先设置 GitHub 库」

    说明还没配好三项之一：账号令牌、仓库名、以及账号是「当前账号」。回本设置页把两页都存一遍； 设置页右上角变绿「已就绪」才说明齐了。

    提示 403 Resource not accessible

    令牌没勾 repo，或者用的是 fine-grained 令牌但没给 Contents / Administration 写权限。 换 classic 令牌勾 repo 最省事。

    提示「是公开仓库，同步已被禁止」/「能匿名读取」

    GitHub 仓库设置 → 最下面 Danger Zone → Change visibility → 改成 Private。插件每次都探一次匿名访问， 就是这个原因：字体一旦公开可下，性质就从「个人备份」变成「公开分发」。

    提示连不上 GitHub / 超时

    插件走系统代理（读 HTTPS_PROXY）。公司网络若拦截 api.github.com，请让代理放行； 本地主程序的接口是直连的，不走代理。

    同步失败说「本地 API 502」

    老版本的代理问题，已在 0.1.1 修掉。仍出现就把 %APPDATA%\FontManager\activation.log 里带 [plugin:com.fontmanager.font-sync] 的行发我。

    字体传到哪了？会进 git 历史吗？

    字体本体只作为 release 附件（lib-0001 这类 release 下的 zip），不进 git。 git 里只有 ops/<设备号>/<时间>.json 这种几十 KB 的记账文件。
