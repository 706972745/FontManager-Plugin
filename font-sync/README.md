# 字体库同步（GitHub）

把 FontManager 的字体库**按字族打包**，增量同步到**你自己的私有 GitHub 仓库**。
换机器、重装系统、多台电脑之间对齐——不用再拿 U 盘拷 6 GB。

> 只上传「变了」的字族。改一个 60 KB 的英文字体，不会重传 520 MB。

---

## 它到底做了什么

1. 从主程序的本地 API 读出全部字面（`GET /fonts`），按**字族**分组；
2. 每组用「路径 + 大小 + 修改时间」算一个指纹，和上次同步的指纹比对 ——
   **没变就整族跳过**（不打包、不读文件内容）；
3. 变了的族打成一个确定性 zip（条目排序、时间戳写死、字体 STORED），算 sha256；
4. 哈希和上次一样（只是挪了位置或动了 mtime）→ **不上传**；
5. 真变了才传到私有仓库的 release asset，文件名 `<字族>__<哈希前12位>.zip`；
6. 每批同步写一份记账文件 `ops/<设备号>/<时间戳>.json`，一次 commit 提交（原子）；
7. 被替换的旧 asset 不立刻删，记进 `pendingDeletes`，**7 天后**才物理删
   （给「另一台机器用旧版覆盖新版」留反悔窗口）。

## 三条安全硬闸

这个插件会把你机器上的字体送进云端，所以默认是「宁可不同步」：

| 闸 | 规则 | 为什么 |
|---|---|---|
| **仓库必须真私有** | 除了看 `private` 字段，还会**匿名**请求一次仓库接口；200 就中止 | 手滑把仓设成公开，等于把商用字体摆到公网上 |
| **判不清授权的不传** | `copyrightClass = unknown` 的族默认跳过 | 未知授权的字体不该出现在任何服务器上（可在设置里放开） |
| **令牌加密落盘** | Windows DPAPI（`CryptProtectData`），只有当前 Windows 用户能解 | 插件目录被拷走也解不开令牌；解不开就只留在内存里，绝不写明文 |

> 这三条只是「降低你自己踩坑的概率」，不是法律意见：字体授权写着「不得再分发」时，
> 传到任何第三方服务器都超出授权范围。私有仓被发现概率极低，但不等于合规。
> 详见 `软件迭代/GitHub同步实现文档.md`。

## 安装

1. 下载本目录（或 Release 里的 `font-sync.zip`），解压出 `font-sync` 文件夹；
2. 打开 FontManager → **设置 → 插件 → 打开插件目录**，把文件夹放进去；
3. **设置 → 插件**里打开开关（没看到就点「重新扫描」）。

插件只依赖 Python 标准库，**不用装任何第三方包**。机器上没有 Python 3.10+ 时，
把任意一个自带运行时的插件里的 `runtime/` 目录复制过来，并在 `plugin.json` 里加
`"interpreterPath": "runtime/python.exe"` 即可。

## 首次配置

1. **建令牌**：GitHub → Settings → Developer settings → Personal access tokens →
   **Tokens (classic)** → Generate new token → 勾 **`repo`** → 生成后复制。
   （classic 才够用；fine-grained 令牌对 release / git 数据的组合权限很麻烦。）
2. 打开 FontManager → 设置 → 插件 → 本插件那一行右侧**齿轮** → 粘贴令牌 → **测试连接**；
3. 仓库名默认 `fontmanager-library`，所有者留空＝令牌本人。仓库不存在会自动**建私有仓**；
4. 点 **预演一次**：只列计划、不传任何东西 —— 首次全量前建议先看一眼要传多少。

## 三种用法

| 位置 | 菜单项 | 做什么 |
|---|---|---|
| 任意字族右键 | 同步这个字族到 GitHub | 只处理这一个族（改了一款字体时最快） |
| 设置 → 插件 → 该行右键 | 立即同步（全部） | 全量扫一遍，只传变化的族 |
| 同上 | 预演本次同步（不传） | 只出计划：多少族、多少 MB，什么也不传 |
| 同上 | 同步设置… | 令牌、仓库名、单族上限、旧版本保留天数 |
| 同上 | 打开同步状态目录 | 直接打开插件目录（`state.json` / `config.json` 都在这） |

同步在后台线程跑，进度写进软件日志（`%APPDATA%\FontManager\activation.log`，
带 `[plugin:com.fontmanager.font-sync]` 前缀），结束弹一条 toast。

## 仓库里长什么样

```
fontmanager-library（私有）
├── README.md                      ← 自动初始化时生成
├── ops/
│   └── 3f9a1c2b7d4e/              ← 每台机器一个目录（deviceId）
│       └── 1730000000000.json     ← 一批同步的记账（族名、asset 名、哈希、大小）
└── Releases
    ├── lib-0001                   ← 分桶：一个 release 最多 888 个 asset
    │   ├── 思源宋体__a1b2c3d4e5f6.zip
    │   └── Barmeno__9f8e7d6c5b4a.zip
    └── lib-0002                   ← 用满了才出现
```

- **字体二进制不在 git 历史里**（只作为 release asset），所以仓库不会因为反复同步而膨胀；
- release 标记为 prerelease，避免它出现在别人看你的 Releases 页面时排在前面（私有仓无所谓）；
- 一个 zip 里除了字体，还带同目录的授权文档（`OFL.txt` / `LICENSE` / `版权说明.txt` 等，
  文本类才带），换台机器能看到授权原话。

## 已知限制（写清楚，免得你踩）

| 限制 | 现状 |
|---|---|
| **下载/恢复还没做** | 目前是「只上不下」。换机器恢复要等 0.2（读取 release、按 ops 合并、写回本地库） |
| 单族上限 | 默认 400 MB，超了跳过并在日志里报出来（防一个巨型族卡死整轮） |
| 一个 release 装 888 个 asset | 超过自动开 `lib-0002` |
| GitHub 单文件上限 | 2 GiB（产品限制）；插件的单族上限先卡在 400 MB |
| 只有 Windows | 令牌保险箱用 DPAPI，`state.json` 路径按插件目录走 |
| 中文/特殊字符族名 | asset 名保留中文，只清掉 `\/:*?"<>|` 与空白 |

## 排错

| 现象 | 原因 / 处理 |
|---|---|
| `还没填 GitHub 令牌` | 齿轮面板里填 classic token（勾 `repo`） |
| `401` | 令牌过期或没勾 `repo` |
| `403 Resource not accessible` | 令牌没有 `repo`；或目标是别人的仓（intranet 限制） |
| `仓库匿名可读，已中止` | 仓库其实是公开的 —— 这是**故意的**，改成私有再来 |
| `同步失败：本地 API 401` | 主程序的插件开关刚开、令牌还没签发；关掉再打开开关 |
| 传得很慢 | 上行带宽决定，6 GB 首次全量以小时计；之后只有增量 |
| 想从头再来 | 关掉插件 → 删 `state.json`（不清远端）或连同远端 release 一起删 |

日志里每一步都有：计划多少族、跳过多少、每个族传了多少字节、哪个族失败。

## 开发

```bash
cd font-sync
python -m unittest discover -s tests -v     # 16 个核心单测，不联网、不需要主程序
```

模块划分：

| 文件 | 职责 |
|---|---|
| `main.py` | 协议（stdin/stdout JSON 行）、菜单分派、设置面板、后台线程 |
| `syncer.py` | 取清单 → 分组 → 计划 → 上传 → 记账 → 清旧 asset |
| `packer.py` | 确定性 zip、哈希、asset 命名、授权文档收集 |
| `gh.py` | GitHub REST 封装（重试、限速、302、分桶、Git Data API 提交） |
| `store.py` | `config.json` / DPAPI 令牌 / `state.json` |

设计口径与实现细节全部以 `软件迭代/GitHub同步实现文档.md` 为准。
