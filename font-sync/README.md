# 字体库同步（GitHub）

把 FontManager 的字体库**按字族打包**，增量同步到**你自己的私有 GitHub 仓库**；
反过来也行 —— 在任何一台新电脑上**把字体下载回本机字体库**（自动重扫，界面立刻可见）。
换机器、重装系统、多台电脑之间对齐——不用再拿 U 盘拷 6 GB。

> 只上传「变了」的字族。改一个 60 KB 的英文字体，不会重传 520 MB。
> 上传的是**字体文件本体**（原文件字节，一个不改，外加同目录的授权/说明文档），不是链接。

**仓库是每个人自己的**：插件不预设任何仓库、也不带作者的账号。你可以在同一台机器上
保存多个 GitHub 账号（各自的令牌）和多个库，随时切换。**没配好账号与库之前，插件不会同步任何内容。**
配置步骤见下面的 [首次配置](#首次配置必须配好才能用)。

设置面板开在一个**窗口**里（0.8.0）：主程序 ≥1.4.3 时由主程序弹**应用内窗口**加载面板；
老版本主程序退回 Edge `--app` 无边框独立窗口（再不行退回默认浏览器）。面板由插件在本机起
一个小服务（`127.0.0.1`、一次性 key、45 分钟无操作自动关），里面有一页**权限说明**
（令牌要开哪几项、每项为什么需要）和一页**从零开始的教程**。为什么不用 tkinter：
插件自带的是 Python embeddable 发行版，**不含 tkinter**，而且用户机器装没装 Python 不该影响设置。

---

## 它到底做了什么

1. 从主程序的本地 API 读出全部字面（`GET /fonts`），按**字族**分组；
   **系统字体（`C:\Windows\Fonts` 那 300 多个）直接跳过** —— 它们是 Windows 自带的，
   不可再分发，也不属于你的字体库；
2. 每组用「路径 + 大小 + 修改时间」算一个指纹，和上次同步的指纹比对 ——
   **没变就整族跳过**（不打包、不读文件内容）；
3. 变了的族打成一个确定性 zip（条目排序、时间戳写死、字体 STORED），算 sha256；
4. 哈希和上次一样（只是挪了位置或动了 mtime）→ **不上传**；
5. 真变了才传到私有仓库的 release asset，文件名 `<字族>__<哈希前12位>.zip`；
6. 每批同步写一份记账文件 `ops/<设备号>/<时间戳>.json`，一次 commit 提交（原子）；
7. 被替换的旧 asset 不立刻删，记进 `pendingDeletes`，**7 天后**才物理删
   （给「另一台机器用旧版覆盖新版」留反悔窗口）；
8. **本地删掉的字族，全量同步时会把远端那份一起删掉**（默认如此，可在设置里关掉）——
   备份和库保持一致，而不是只增不减的垃圾堆。
9. **标签 / 评分 / 收藏 / 备注也跟着一起备份**（0.9.0 起）：一份小文件 `ops/curation.json`，
   恢复字体时自动合并回本机。合并规则是并集 / 取高分 / 备注取长的，**多台机器谁先提交都不会覆盖别人**；
   分组（collections）暂不同步 —— 主程序还没有写分组的 API。

## 三条安全硬闸

这个插件会把你机器上的字体送进云端，所以默认是「宁可不同步」：

| 闸 | 规则 | 为什么 |
|---|---|---|
| **仓库必须真私有** | 除了看 `private` 字段，还会**匿名**请求一次仓库接口；200 就中止 | 手滑把仓设成公开，等于把商用字体摆到公网上 |
| **判不清授权的不传** | `copyrightClass = unknown` 的族默认跳过 | 未知授权的字体不该出现在任何服务器上（可在设置里放开） |
| **令牌不在插件里** | 存进 **Windows 凭据管理器**（`FontManager/font-sync/vault`），回退时存 `%APPDATA%\FontManager\font-sync\vault.bin`（DPAPI 加盐密文） | 插件 ZIP / 插件目录 / 代码里都翻不到令牌，拷走插件也带不走；旧版插件目录里的 `secret.bin` 会自动迁移并删除 |
| **上传与看令牌要验证本人** | 先在浏览器登录「令牌所属」的 GitHub 账号并输入一次性验证码（Device Flow） | 别人坐在这台电脑前也传不了、复制不了令牌；**下载字体不需要验证** |

> 这四条只是「降低你自己踩坑的概率」，不是法律意见：字体授权写着「不得再分发」时，
> 传到任何第三方服务器都超出授权范围。私有仓被发现概率极低，但不等于合规。
> 详见 `软件迭代/GitHub同步实现文档.md`。

## 安装

1. 下载本目录（或 Release 里的 `font-sync-0.8.11.zip`），解压出 `font-sync` 文件夹；
2. 打开 FontManager → **设置 → 插件 → 打开插件目录**，把文件夹放进去；
3. **设置 → 插件**里打开开关（没看到就点「重新扫描」）。

### 运行环境 / 依赖

| | |
|---|---|
| 解释器 | **Python 3.10+**，本插件**不自带** |
| 从哪来 | 软件「设置 → 插件 → 运行时管理」下载的 Python，或系统已装的 Python 3.10+ |
| 第三方库 | **无**（零第三方依赖，全是标准库） |
| 系统组件 | Windows 凭据管理器、`crypt32.dll` / `kernel32.dll`（DPAPI）、浏览器（设置面板） |
| 适用平台 | **Windows** |

软件插件清单这一行会标出「需要 Python」；机器上没 Python 时徽标变红显示
「缺少运行时」，去「运行时管理」点「下载补全」即可 —— **不是插件坏了，也不是软件
版本不对**。不想下载运行时的话，也可以把任一自带运行时插件的 `runtime/`
复制过来，并在 `plugin.json` 里加 `"interpreterPath": "runtime/python.exe"`。

## 首次配置（**必须配好才能用**）

插件不预设任何仓库、也不带作者的任何账号 —— **每个人用自己 GitHub 账号下的私有库**。
没配好「账号 + 仓库」之前，点同步只会弹一句「先设置 GitHub 库」并打开设置面板，不会传任何东西。

### 第 1 步：建一个令牌（每个账号一个）

1. 登录你要用的那个 GitHub 账号（可以是 A 账号，也可以给家里另一台机器用 B 账号）；
2. **Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token**；
3. 名字随便写（例如 `fontmanager-sync`），有效期按自己喜好，**勾 `repo`**（整个大项）；
4. 生成后**立刻复制**（页面关掉就再也看不到）。

> 为什么必须 classic：fine-grained 令牌要同时具备「Releases 读写 + Contents 读写」的组合，
> 配置项多且容易漏；classic 勾一个 `repo` 就够。

### 第 2 步：在插件里存令牌

FontManager → **设置 → 插件** → 本插件那一行右侧**齿轮**（或右键插件行 →「设置 GitHub 库…」），
会打开设置面板窗口 → 停在「账号与令牌」页：

1. 令牌粘进输入框（显示成圆点，可点「显示」核对）；
2. 点 **测试并保存** —— 面板会用这个令牌真去问一次 GitHub，逐项给出「读账号 / 建仓写权限 / 目标库可用性」的结果；
3. 令牌交给 **Windows 凭据管理器** 保管（`FontManager/font-sync/vault`），
   **插件目录里没有任何令牌文件**，插件 ZIP 被拷走也带不走；换 Windows 账号同样打不开。
   凭据管理器不可用时回退到 `%APPDATA%\FontManager\font-sync\vault.bin`（DPAPI 加盐密文），
   两者都不可用就只在内存里有效并明确告警，绝不写明文。旧版插件目录的 `secret.bin`
   会在首次读取时自动迁移并删除。

面板里的「权限说明」页是给**第一次用**的人看的：它列出插件会发的每一个请求分别需要哪项权限
（建私有仓 `POST /user/repos`、上传 release asset、写 Git Data、删旧 asset，全是 `repo`），
以及**不需要**的权限（不碰 Actions、组织设置、别的仓库）。

### 第 3 步：指定仓库

「同步到哪个库」页是左右两块，**挑一块点一下就完事**，不用手打 owner/name：

| 你的情况 | 怎么做 |
|---|---|
| 已经有私有库 | 点 **刷新列表** → 下拉里挑一个（私有库排前面，公开库单独一组并标注「不能用」）→ **用这个库**。插件当场检查「是不是私有 / 能不能匿名读」，通过就自动存成当前库 |
| 还没有仓库 | 右边 **建好并用它**（名字默认 `fontmanager-fonts`，可改）。建的是 private 仓库，建完自动设为当前库，不用再去网页点一遍 |
| 已有空仓库 | 同上，选它就自动初始化（首次同步会放一个 README 建出首个提交） |
| 已有内容的私有库 | 直接选；插件的 `ops/` 目录与 `lib-0001` 之类的 release 都是新加的，不动你原有内容 |
| 想用组织或别人的库 | 展开 **「手动填写所有者 / 仓库名」**，所有者填组织/对方登录名（令牌得有那个库的写权限） |

**几个防呆**（都试过误操作）：

- 仓库名**边打边校验**，中文/空格/斜杠当场变红并禁用按钮，不会等 GitHub 回 422；
- 名字正好是当前库 → 按钮变「已是当前库」并禁用，防止你手一抖又建一个；
- 建库时如果这个名字**已经存在**，不会报错，直接切过去（省一步，也不会建出重名失败）；
- 换到另一个库会**先确认**，因为换库等于清掉本机记录、按新库重新全量上传（旧库的备份不动）；
- 「刷新列表」会自动选中当前库，一眼看到自己在用哪个；
- 「打开插件目录」失败会把原因写在页面上，并给一个「复制路径」的保底通道。

成功的标志是页面中间那条变绿：**「当前库：你的名字/xxx（已就绪）」**。
如果要手填，填完点 **检查这个库**，绿字才是可用状态：

- `可用（私有，默认分支 main）` ✅
- `是**公开**仓库，同步已被禁止` ❌ —— 先去 GitHub 把仓库改成 Private
- `能匿名读取，同步已被禁止` ❌ —— 同上，这是最关键的一道闸

设置会记住这个库，下次直接用；用过多个库时，「手动填写」里的仓库名输入框会把历史库列出来。

### 第 4 步（强烈建议）：先预演

右键插件行 → **预演本次同步（不传）**：只列「多少族、多少 MB」，不打包、不联网上传。
看完心里有数再点「立即同步（全部）」。

结果会写成 **「全库 N 族 → 本次会传 M 族（跳过 …）」**。M 比 N 小很多时，看括号里的原因：

- `XXXX 族版权未知` —— **只有你手动勾上**「不同步版权未知的字族」时才会出现（0.8.13 起默认不勾，
  整库都备份）。个人字库通常九成以上属于这一类，勾上后预演只剩几百个族。
- `X 族超大` —— 超过「单族上限（默认 85 MB）」，比如思源宋体整族 160 MB。调到 **200 MB** 就能把它们也带上（GitHub 单文件上限是 2 GiB，很宽）。

> 同步规则里的勾选框和两个数字框**改完立刻生效**（不需要再点「保存规则」），
> 面板底部的提示会写「规则已保存」；保存失败会把勾选滚回真实状态并报错。

## 下载回本机（另一台电脑怎么把字体拿回来）

0.8.0 新增两种按需下载：

- **右键单族下载**：在任何字族上右键 →「从 GitHub 下载这个字族」—— 知道缺哪个就补哪个；
- **面板「补缺」页**：导入快照后（界面会提示「其中 N 个本机没有」），到面板选这个快照点
  「分析缺失」—— 插件列出缺哪些、标出哪些能从你的 GitHub 库直接补，勾选 → 下载 → 自动重扫。
  （需要插件令牌有 `read:snapshot` 权限 —— 0.8.0 起自带；老令牌重启 FontManager 即可拿到。）

上传到仓库的是**字体文件本体**（zip 里就是原来的 `.ttf/.otf`，字节不改，外加授权/说明文档）。
所以在任何一台装了 FontManager + 本插件、并按上面步骤配好**同一个库**的电脑上：

1. 右键插件行 → **从 GitHub 下载到这台电脑**（或先「预演下载（看会拉哪些）」）；
2. 插件把远端每个字族的 zip 下载回来、校验 sha256、解压进**字体库**对应字族目录
   （默认 = FontManager 当前的字体库；设置面板「下载回本机」页可以改目录）；
3. 下载完自动让 FontManager 重新扫描 —— 字族直接出现在界面上。

几个刻意的防呆：

- **本机已有的字族不重复下载**；同名文件内容不同时**不覆盖**（要覆盖得在面板里勾「覆盖本机同名文件」）；
- 下载的 zip 会先校验哈希，对不上（下载损坏 / 被篡改）就拒绝写盘；
- 目标字体库目录按「设置里填的 > FontManager 当前字体库 > 按字体路径推断」决定，
  实际会写到哪里，面板里明明白白写着；
- 首次全量上传很大时可以分批传（`config.json` → `sync.batchFamilies`，默认一轮 100 个族）。

## 设置面板（窗口，含权限说明与教程）

入口：设置 → 插件 → 本插件**齿轮**，或右键插件行 →「设置 GitHub 库…」。
面板由插件在本机起一个小服务（只绑 `127.0.0.1`，一次性随机 key，45 分钟无操作自动关）。

| 页签 | 内容 |
|---|---|
| **账号与令牌** | 粘令牌 → 测试并保存；已存账号列表（切换 / 移除）；本机到底存了什么文件 |
| **同步到哪个库** | **选库（下拉列出你账号下的私有库，一键「用这个库」）／一键新建私有库**；手动填写所有者/仓库名（组织库）；同步规则（是否传版权未知、**删除本地已删字族的远端备份**、单族上限、旧版本保留天数）；预演 / 立即同步 |
| **下载回本机** | 看远端有什么（族数 / 总大小）、下载目录、是否覆盖同名；预演下载 / 开始下载，带进度条 |
| **权限说明** | 令牌要开哪几项：功能 → 调用接口 → 需要权限 → 为什么；**不需要**的权限清单；为什么不用 fine-grained；本插件对主程序的 `read:fonts` / `write:fonts` 权限；一键「现在体检」逐项实测 |
| **新手教程** | 从零五步（含「已预勾 repo」的建令牌直链）、第二台电脑怎么做、7 条常见问题 |
| **高级** | 设备号、已同步族数、上次同步时间、插件目录、清空本机配置与令牌 |

> 面板**看不到令牌原文**：接口只回打码后的 `ghp_abc…wxyz`，令牌只在 Python 进程里流转。
> 页面本身也不接受外部来源的请求（没有 CORS 头，key 不对一律 403）。

## 多账号 / 多个库

- **多账号**：「账号与令牌」页下方列出已保存的账号（带「当前」标记），点 **切换** 换账号、**移除** 删本机令牌。
  新增账号就是把另一个账号的令牌粘进去点「测试并保存」，各自加密存在同一个 `secret.bin` 里。
- **多个库**：填不同「所有者/仓库名」保存即可；用过的库会进「最近的库」候选，输入框里直接选。
- **一台机器只用一套 `state.json`**：换库时插件会按 `state.json` 里记的「族 → 哈希」判断要不要重传，
  换了库就等于换了远端，首次会全量传一遍（这是预期行为，别当成 bug）。
- 移除账号只是删掉本机保存的令牌，**不影响** GitHub 上的仓库和里面的字体。

## 发给同事（不用 GitHub 也能发）

插件不需要发布到 GitHub 才能给人用 —— ZIP 在 **releases/latest** 里就有（推 `font-sync/**`
到 main 会触发 `Plugin Release` 工作流自动打包并覆盖上传），也可以本地打：

```bash
python .github/package_plugin.py       # 输出 dist/font-sync.zip 与 dist/font-sync-full.zip
```

- `font-sync.zip`：纯代码，**推荐**。插件本身零第三方依赖，但**需要 Python**：
  到软件「设置 → 插件 → 运行时管理」下载一次共享 Python 3.13，或用系统已装的
  Python 3.10+（1.4.11 起安装包不再内置解释器，别指望开箱就有）；
- `font-sync-full.zip`：代码 + tests，调试用（不含 runtime —— runtime 由主程序注入，
  没必要重复背上 59 MB）。

同事那边只要三步：

1. 解压出 `font-sync` 文件夹；
2. 整个文件夹放进 **FontManager → 设置 → 插件 →「打开插件目录」** 打开的那个目录；
3. 回软件里打开开关（没看到就点「重新扫描」）→ 点齿轮按上面的「首次配置」填自己的令牌和自己的库。

> **打包用白名单**：只收 `main.py / gh.py / store.py / packer.py / syncer.py / panel.py /
> panel.html / plugin.json / README.md / tests/`。`secret.bin`（令牌）、`config.json`、`state.json`
> **永远不会进包** —— 手打包时也要注意这一点，别把自己的令牌连同状态文件一起发出去。

每个人配的是**自己的**账号和库：你发的只是这个工具，同事第一次用仍然要填他自己的 classic token。

## 三种用法

### 进度看哪里

点「预演一次」或「立即同步」之后，按钮下面会出现一条**进度条**，一直在刷新：

```
正在打包第 38/263 个：文鼎霹雳体
已处理 37/263 · 132.0 MB / 863.0 MB · 刚完成 文鼎霹雳体
```

阶段依次是 `读清单 → 算计划 → 核对仓库 → 逐族打包上传 → 清理旧包 → 完成`，
完成或出错时进度条变色并停住。这个进度也写在 `activation.log` 里
（`[plugin:com.fontmanager.font-sync]` 前缀），关掉面板不影响同步 ——
重新打开面板会自动接上正在跑的那一轮。

### 多账号 / 多个库

| | 怎么加 | 怎么切 |
|---|---|---|
| **多个 GitHub 账号** | 在「账号与令牌」页把**另一个账号的令牌**粘进去 → 测试并保存 | 列表里非当前的那行有 **「切换」** 按钮 |
| **同一个账号的多个库** | 「同步到哪个库」页选另一个库 / 新建一个 | 选完点「用这个库」即生效 |

每个账号的令牌各自加密存在同一个 `secret.bin` 里；切换账号**不会**动仓库设置，
但换库会清掉本机的同步记录（重新全量），这一点页面会先问你。

| 位置 | 菜单项 | 做什么 |
|---|---|---|
| 任意字族右键 | 重新同步这个字族（强制重传） | 只处理这一个族；**不吃「没变化」判断**，每次都真打包 —— 换了同尺寸的字体也能传上去 |
| 设置 → 插件 → 该行右键 | 立即同步（全部） | 全量扫一遍，只传变化的族 |
| 同上 | 预演本次同步（不传） | 只出计划：多少族、多少 MB，什么也不传 |
| 同上 | 设置 GitHub 库… | 浏览器面板：账号（多账号切换）、仓库、同步规则 |
| 同上 | 使用教程与权限说明… | 直接打开面板的「教程」页（第一次用就从这看） |
| 同上 | 打开同步状态目录 | 直接打开插件目录（`state.json` / `config.json` 都在这） |

同步在后台线程跑，进度写进软件日志（`%APPDATA%\FontManager\activation.log`，
带 `[plugin:com.fontmanager.font-sync]` 前缀），结束弹一条 toast。

## 仓库里长什么样

```
fontmanager-library（私有）
├── README.md                      ← 自动初始化时生成
├── ops/
│   └── 3f9a1c2b7d4e/              ← 每台机器一个目录（deviceId）
│       └── 1730000000000.json     ← 一批同步的记账（族名、asset 名、哈希、大小）
└── Releases
    ├── lib-0001                   ← 分桶：一个 release 最多 888 个 asset
    │   ├── 思源宋体__a1b2c3d4e5f6.zip
    │   └── Barmeno__9f8e7d6c5b4a.zip
    └── lib-0002                   ← 用满了才出现
```

- **字体二进制不在 git 历史里**（只作为 release asset），所以仓库不会因为反复同步而膨胀；
- release 标记为 prerelease，避免它出现在别人看你的 Releases 页面时排在前面（私有仓无所谓）；
- 一个 zip 里除了字体，还带同目录的授权文档（`OFL.txt` / `LICENSE` / `版权说明.txt` 等，
  文本类才带），换台机器能看到授权原话。

## 已知限制（写清楚，免得你踩）

| 限制 | 现状 |
|---|---|
| 单族上限 | 默认 **85 MB**，超了跳过并在日志里报出来（防一个巨型族卡死整轮）。中文全套字库建议调到 **200 MB**（覆盖思源宋体这类 160 MB 的族）；GitHub 单个 asset 上限 2 GiB |
| 删除的判定 | 只在**全量同步**时判断「本地少了哪些族」（单族同步不推断，否则会把其它族全删了）。判断依据是本机 `state.json` 里记过的族 |
| 跨机器删除 | A 机删了某族并同步，B 机还留着它 —— B 机下次同步会**再传一份回去**。多机一致的第 2 版逻辑（op 合并）还没做 |
| 换库后第一轮 | 换库会清掉本机的同步记录（那些 asset 属于旧库），所以新库要**重新全量传一遍**，这是有意的 |
| 一个 release 装 888 个 asset | 超过自动开 `lib-0002` |
| GitHub 单文件上限 | 2 GiB（产品限制）；插件的单族上限默认 85 MB，建议大库调到 200 MB，改完立刻生效 |
| 只有 Windows | 令牌保险箱用 Windows 凭据管理器 / DPAPI，设置面板依赖浏览器与系统对话框 |
| 上传前要登录 GitHub | 上传与「复制令牌」会要求浏览器登录对应账号并输入一次性验证码；下载不需要 |
| 中文/特殊字符族名 | asset 名保留中文，只清掉 `\/:*?"<>|` 与空白 |

## 排错

| 现象 | 原因 / 处理 |
|---|---|
| `还没填 GitHub 令牌` / 一直提示「先设置 GitHub 库」 | 设置面板「账号与令牌」页填 classic token（勾 `repo`），再到「同步到哪个库」页填仓库名并保存 |
| `401` | 令牌过期或没勾 `repo` |
| `403 Resource not accessible` | 令牌没有 `repo`；或目标是别人的仓（intranet 限制） |
| `仓库匿名可读，已中止` | 仓库其实是公开的 —— 这是**故意的**，改成私有再来 |
| `同步失败：本地 API 401` | 主程序的插件开关刚开、令牌还没签发；关掉再打开开关 |
| 传得很慢 | 上行带宽决定；0.8.14 起字体用 DEFLATE 压，实测小族省四成、中文大族省近两成，整库 6.85 GB 大约只传 4.4 GB；之后只有增量 |
| 传到一半断了 / 报 `ConnectionReset` | 0.8.14 起自动重试：单族失败会整包再传一次（GitHub 不支持断点续传），仍失败就记进日志、清掉 502 留下的空壳 asset，下一轮再补；其它族不受影响 |
| 升级到 0.8.14 后第一次同步全都在重传 | 正常：哈希从「zip 字节」换成「内容哈希」（否则压缩会让幂等失效），旧资产名对不上，会整库重传一次，之后恢复增量 |
| `上传前请先在设置面板完成 GitHub 账号登录验证` | 直接在插件右键菜单点同步时没有验证票据；打开设置面板点一次「立即同步」，按弹窗在浏览器登录对应账号输验证码 |
| 验证弹窗要 Client ID | 第一次用需要建一个 GitHub OAuth App（Developer settings → OAuth Apps → New OAuth App），名称随意、回调填 `http://localhost`，**创建后必须勾上 `Enable Device Flow` 再 Update application**，把公开的 **Client ID** 粘进弹窗保存即可（0.8.12 起弹窗里有「先检测」按钮，会直接告诉你能不能用）；插件不需要也不会存 client_secret |
| `GitHub 拒绝了这次请求（HTTP 400）` / 旧版显示 `连不上 GitHub 的登录验证服务：HTTP Error 400` | 99% 是 OAuth App 没勾 `Enable Device Flow`（网络没坏，是 GitHub 明确拒绝）。0.8.12 起弹窗会直接指到这个开关；不想建 OAuth App 也可以点弹窗里的「改用令牌校验」，用本机已保存的令牌向 GitHub 确认身份 |
| `登录的是 xxx，当前令牌属于 yyy` | 浏览器里登录的 GitHub 账号和令牌所属账号不一致，退出后用对应账号重新登录再试 |
| **同步显示「完成」，但 GitHub 的 release 里没有包** | 0.6.0 及以前的 bug：上传没带 `Content-Type`，GitHub 回 422，而代码把任何 422 都当「同名已存在」按成功处理。0.6.1 起上传按 `application/octet-stream` 发，且只有真正的 `already_exists` 才算成功 |
| 点「预演 / 立即同步」只回一句 `unknown endpoint` | 0.4.0 及以前的前端 bug：这两个按钮没带请求体，被发成 GET，后端只在 POST 处理。升级到 0.4.1 即可 |
| 想从头再来 | 关掉插件 → 删 `state.json`（不清远端）或连同远端 release 一起删 |
| 删了字体，远端还在 | 删除只发生在**全量同步**（「立即同步（全部）」）时，单族同步不动别的族；并且设置里「同时删除 GitHub 上的备份」要保持开启 |
| 一次少了一大半的族，结果一个都没删 | 这是保险丝：本地读到的族数不足上次的一半（扫描没跑完 / 库没挂上）时，这一轮不删任何远端内容，日志里会写原因 |

日志里每一步都有：计划多少族、跳过多少、每个族传了多少字节、哪个族失败。

|---|---|

| `store.py` | `config.json` / DPAPI 令牌 / `state.json` |
